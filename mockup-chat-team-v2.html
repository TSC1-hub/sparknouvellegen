SPARK comme questionneur

5 postures d'interrogation — SPARK ne fournit pas de contenu, il pousse la team à creuser. Upload de document conservé pour le mode "Analyse critique". Réponses en markdown libre, pas de blocs JSON balisés.

Les 5 modes de questionnement
🔬
Question scientifique
SPARK creuse un concept ou un phénomène lié au projet avec des questions de fond : mécanismes, preuves, limites. Oblige la team à distinguer ce qu'elle sait vraiment de ce qu'elle suppose.
Toujours dispo
💥
Challenge notre idée
SPARK joue l'avocat du diable. Il soulève des objections, des contradictions, des cas limites — sans jamais donner la solution. La team doit défendre ou reformuler son idée par elle-même.
Toujours dispo
📄
Analyse critique du document
La team joint un PDF, une image ou un texte. SPARK pointe les failles, les manques, les biais, les questions sans réponse — mais ne rédige pas à leur place. Nécessite d'attacher un fichier.
Necessite 📎
⚖️
Joue le jury
SPARK simule un jury exigeant : faisabilité, impact réel, éthique, modèle économique. Il pose les questions que le vrai jury posera. La team s'entraîne à répondre sous pression sans script.
Toujours dispo
🕳️
Cherche nos angles morts
SPARK explore systématiquement ce que la team n'a pas vu : parties prenantes oubliées, effets de bord, hypothèses implicites, risques invisibles. Sans apporter les réponses.
Toujours dispo

Principes d'implémentation
🎭
Modes → system prompt injecté dynamiquement
Un objet SPARK_MODES associe chaque mode à un bloc de system prompt ajouté dans callMistral() avant l'envoi. Aucun bloc JSON balisé — SPARK répond en markdown libre. Le mode actif est stocké dans une variable _activeMode côté client, remis à null à chaque nouvelle conversation.
SPARK_MODES[mode].systemPrompt _activeMode = null par défaut
🖱️
UX — sélection du mode
Les 5 boutons de mode s'affichent au-dessus de l'input, toujours visibles. Un clic active le mode (surbrillance), un second clic le désactive (retour au mode libre). Le placeholder de l'input change selon le mode actif. Pour le mode "Analyse critique", le bouton 📎 est mis en avant visuellement.
renderModeBar() toggleMode(mode)
📎
Upload fichier → contexte Mistral (conservé)
FileReader lit le fichier côté client. PDF/TXT → texte brut injecté comme message système [DOCUMENT JOINT]\n{contenu}. Image → base64 via Mistral Vision. Upload disponible dans tous les modes, particulièrement pertinent pour "Analyse critique". Aucun stockage côté Supabase.
Client-only parse Max 4 Mo / 8000 tokens PDF
🚫
Ce qu'on supprime vs le mockup v1
Blocs SPARK_FICHE / SPARK_PLAN / SPARK_ANALYSE abandonnés — SPARK comme questionneur n'a pas à générer du contenu structuré. Chips contextuels par étape abandonnés — trop directifs, contraires à la philosophie. SPARK_HTML_START…END conservé pour la vitrine uniquement.
